2. Cum functioneaza deploy-ul

  1. Proprietara (sau tu) editeaza ceva — fie din CMS (/admin), fie cu git push.
  2. CMS-ul face automat un commit in GitHub.
  3. Cloudflare Pages detecteaza commit-ul si rebuild-uieste site-ul (30-60 secunde).
  4. Noul site e live automat pe critcoffeeshop.com.

Build command: npm run build
Output dir: dist
Node version: 22 (setat ca env var NODE_VERSION=22 in Cloudflare Pages)

Daca build-ul esueaza: Du-te in Cloudflare → Workers & Pages → critcoffeeshop → Deployments. Vezi log-ul ultimului deploy. Cele mai frecvente cauze: eroare de sintaxa in JSON (virgula lipsa), sau o imagine referita in markdown care nu exista in /media.

3. Setup OAuth Worker (INCA DE FACUT)

Fara acest pas, CMS-ul (/admin) nu va functiona cu buton de login. Pana atunci, Sveltia CMS permite login cu Personal Access Token (PAT) — dar asta nu e user-friendly pentru proprietara.

Pas 1 — Creaza GitHub OAuth App

  1. Du-te pe github.com/settings/applications/new
  2. Completeaza:
    • Application name: critcoffeeshop CMS
    • Homepage URL: https://critcoffeeshop.com
    • Authorization callback URL: https://sveltia-cms-auth.SUBDOMAIN.workers.dev/callback (aflat la Pas 2)
  3. Apasa „Register application"
  4. Copiaza Client ID
  5. Apasa „Generate a new client secret", copiaza Client Secret

Pas 2 — Deploy Cloudflare Worker

  1. Du-te pe github.com/sveltia/sveltia-cms-auth
  2. Apasa butonul „Deploy to Cloudflare Workers"
  3. Conecteaza contul Cloudflare al proprietarei
  4. Dupa deploy, copiaza URL-ul Worker-ului (ex: https://sveltia-cms-auth.xyz.workers.dev)
  5. In Cloudflare → Workers → sveltia-cms-auth → Settings → Variables:
    • GITHUB_CLIENT_ID = Client ID de la Pas 1
    • GITHUB_CLIENT_SECRET = Client Secret (apasa Encrypt)
    • ALLOWED_DOMAINS = critcoffeeshop.com
  6. Intoarce-te la GitHub OAuth App si actualizeaza callback URL cu URL-ul real al Worker-ului + /callback

Pas 3 — Actualizeaza config.yml

In public/admin/config.yml, linia base_url — inlocuieste placeholder-ul cu URL-ul Worker-ului:

backend:
  name: github
  repo: Botis0409/critcoffeeshop
  branch: main
  base_url: https://sveltia-cms-auth.XYZ.workers.dev

Commit + push. Asteapta rebuild. Testeaza la critcoffeeshop.com/admin.

Pas 4 — Cont GitHub pentru proprietara

  1. Fa-i cont GitHub gratuit cu emailul ei
  2. Adaug-o ca collaborator: gh repo edit --add-collaborator USERNAME-UL-EI sau din GitHub → Settings → Collaborators
  3. Ea accepta invitatia din email
  4. Testeaza: deschide critcoffeeshop.com/admin pe telefonul ei → „Login with GitHub" → Authorize → e inauntru

4. Cum adaug un capitol nou (pagina noua)

  1. Creaza un fisier in src/content/chapters/, ex: 03-events.md
  2. Frontmatter-ul trebuie sa aiba title, order: 3, description, photos
  3. Creaza pagina Astro in src/pages/, ex: events.astro — copiaza program.astro si schimba order === 3
  4. Adauga link-ul in navigatia din src/layouts/BookLayout.astro
  5. Commit + push

9. Backup si recovery

  • Codul si continutul: totul e in GitHub — git history = backup automat. Orice commit poate fi reversat.
  • Pozele: sunt in repo, in public/media/. Git le pastreaza.
  • Daca stergi repo-ul din greseala: GitHub pastreaza repo-urile sterse 90 de zile — contacteaza support.
  • Daca Cloudflare Pages e sters: recreeaza proiectul, conecteaza acelasi repo, acelasi build config. 2 minute.
